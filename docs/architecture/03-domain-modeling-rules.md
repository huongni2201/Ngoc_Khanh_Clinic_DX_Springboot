# 03 — Domain Modeling Rules

## 1. Aggregate

An Aggregate is a consistency boundary.

An Aggregate Root:

- has identity;
- enforces invariants for objects it owns;
- is the only external mutation entry point for owned entities;
- is loaded/saved atomically from the application perspective.

Do not mark every persisted object as an Aggregate.

## 2. Entity

An Entity:

- has stable identity;
- can change over time;
- is owned by an Aggregate when its consistency is governed by that Aggregate.

Examples:

```text
HealthCheckBatchService
HealthCheckBatchEmployeeService
HealthCheckImportRow
PrescriptionItem
```

## 3. Value Object

A Value Object:

- has no independent lifecycle;
- is immutable;
- validates itself at creation;
- compares by value.

Examples:

```text
IdentificationNumber
Money
ShsCode
AdministrativeSnapshot
ExaminationSite
```

## 4. Constructors

DDD does not prohibit constructors.

Recommended:

```text
private constructor
create(...)
restore(...)
```

Use:

- `create(...)` for new business state;
- `restore(...)` for trusted persistence reconstruction.

Do not expose a public constructor that allows invalid aggregate state.

## 5. Mutation

Avoid setters such as:

```java
setStatus(...)
setPrice(...)
setClosedAt(...)
```

Prefer business methods:

```text
markReady()
start()
finalizeBatch()
close()
cancel()
reopenForRepricing()
repriceService()
releaseToPatient()
```

## 6. Domain invariants

Enforce invariant as close as possible to the owner.

Examples:

```text
CCCD format -> IdentificationNumber
batch lifecycle -> HealthCheckBatch
employee assignment price -> HealthCheckBatchEmployee
prescription issued immutability -> Prescription
adult health-check eligibility -> HealthCheckRecord
```

Cross-aggregate rules belong in application orchestration/domain service if they require multiple repositories.

## 7. Domain and persistence separation

Domain must not use:

```text
MyBatis annotations
database column names
SQL status codes as implementation details
JDBC types
Spring @Component
```

Persistence converter handles translation.

## 8. Restore validation

`restore(...)` should reject impossible state.

Example:

```text
HealthCheckBatch CLOSED
=> finalizedAt != null
=> closedAt != null
```

Do not over-constrain historical data without a documented business rule.

## 9. Time

Do not call system time deeply throughout the domain if deterministic tests matter.

Prefer passing:

```text
now
Clock
domain command timestamp
```

from application layer.

## 10. UUID

Persisted identifiers use UUID v7 generated by the application.

Do not create duplicate public IDs for the same object without a real business need.

## 11. Patient identity

Current MVP:

```text
CCCD is mandatory and unique.
```

Do not reintroduce:

```text
identity_type
passport
fuzzy merge
name/phone duplicate matching
```

without a new requirement/ADR.
